# Mehrsprachigkeit Etappe 1 (DE + EN) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seite und Events auf Deutsch und Englisch: next-intl-Infrastruktur, `/en`-Routing, Sprachauswahl im Header, Event-Sprache, übersetzte App-Oberfläche, Mails in Kontosprache.

**Architecture:** next-intl v4 mit `localePrefix: "as-needed"` (Deutsch ohne Präfix, Englisch unter `/en`). Öffentliche Seiten liegen unter `src/app/[locale]/`; Event-Seiten bleiben unter `src/app/event/[slug]/` und nehmen ihre Sprache aus `events.language`. Serverseitige Texte (API-Fehler, Mails) laufen über einen synchronen `createTranslator` mit expliziter Sprache; Validierung liefert Fehler-Schlüssel statt deutscher Sätze.

**Tech Stack:** Next.js 16.3 (App Router, `proxy.ts`), React 19, next-intl 4.x, Supabase (Auth + Postgres), Drizzle, Zod 4, Vitest (node env, nur `*.test.ts`).

**Spec:** `docs/superpowers/specs/2026-11-13-i18n-design.md`

## Global Constraints

- Sprachen: `["de", "en"]`, Standard `de`. Cookie-Name `NEXT_LOCALE`, Laufzeit 1 Jahr (`maxAge: 31536000`), `path: "/"`, `sameSite: "lax"`.
- Deutsche URLs ändern sich nicht. Englisch nur unter `/en` (Präfix), kein `/de`-Präfix sichtbar.
- Event-Seiten (`/event/<slug>`, `/event/<slug>/info`, OG-Bild, Metadaten) erscheinen immer in `events.language`; keine Sprachauswahl dort.
- Vom Gastgeber geschriebene Texte werden nie übersetzt oder verändert.
- Mails an Gastgeber: Sprache aus `user_metadata.locale`, Fallback `de`.
- Rechtstexte bleiben inhaltlich deutsch; unter `/en/...` mit englischem Rahmen, Hinweis „This document is only available in German.“, `robots: noindex` und `canonical` auf die deutsche URL. Dasselbe gilt in Etappe 1 für `/einladung/*`, `/about`, `/vergleich`.
- Englischer Ton: locker, freundlich, „you“ (entspricht dem deutschen Du). Keine Übersetzung von Markennamen (GASTZILLA).
- Zeitzone bleibt `Europe/Berlin`; nur das Format folgt der Sprache (`de-DE` / `en-GB`).
- Projektregel: **keine Commits/Pushes** durch den Agenten – der Nutzer committet selbst. Commit-Schritte entfallen.
- Migrationen auf der echten Supabase-DB nur nach ausdrücklichem Okay des Nutzers.
- SEO-relevante Änderungen (Metadaten, `hreflang`, Sitemap, strukturierte Daten) mit dem Projekt-Skill `optimizing-seo-aeo-geo`.
- Jede selbst gestartete Dev-Server-Instanz am Ende wieder stoppen.

## Review Focus

1. **Session-Refresh hinter next-intl:** Wenn next-intl umschreibt (`/` → intern `/de`), müssen erneuerte Supabase-Cookies trotzdem bei Browser *und* Server Components ankommen – sonst zufällige Logouts. Test in Task 2.
2. **Gast mit `NEXT_LOCALE=en` öffnet ein deutsches Event:** sieht ausschließlich Deutsch (inkl. Cookie-Banner, Dialoge, API-Fehler), `<html lang="de">`. Test in Task 4 (Sprachauflösung) und Task 9 (Browser).
3. **Cookie-Redirect auf Route-Handler:** `/auth/callback`, `/api/*`, `/event/*`, `/llms.txt`, `/.well-known/*` dürfen nie nach `/en/...` umgeleitet oder nach `/de/...` umgeschrieben werden. Test in Task 2.
4. **Fehlende/abweichende Übersetzungsschlüssel:** `de.json` und `en.json` haben exakt dieselben Schlüssel, keine leeren Werte, gleiche ICU-Platzhalter. Test in Task 1.
5. **Bestehende Events ohne Sprache / Nutzer ohne `locale`:** werden als `de` behandelt, nichts bricht. Tests in Task 4 und Task 8.
